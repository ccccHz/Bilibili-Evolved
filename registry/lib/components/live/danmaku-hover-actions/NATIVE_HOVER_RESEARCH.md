# 原生悬停与生命周期调研（2026-11-04）

本轮为隔离实验，不替换稳定的快照方案，不发布新的悬停实现。

## 当前引擎证据

实际加载的[弹幕引擎](https://s1.hdslb.com/bfs/live-pkg/danmaku/danmaku-v2.js)头部标识版本 `live-danmaku-engine-v2 3.0.10`。播放器为 `Room Player 3.11.9-5a01e0b0`。正式页面没有公开单条弹幕生命周期接口；[播放器接口文档](https://live.bilibili.com/p/html/bilibili-live-player/docs/web-player-biz.iroomplayer.html)也未列出它。

原生滚动对象包含 `mouseEnter`、`mouseLeave`。进入时设置暂停样式、悬停标志和开始时间；离开时补偿运动时间及结束时间。横向坐标在悬停时保持原值。渲染管理器仍按当前渲染时间与对象结束时间比较决定回收，回收的 DOM 会清空并复用。

所以只设置 CSS 暂停，或只调用原生进入方法，均不足以跨过回收期限。这里没有证据支持固定 30 秒的统一生命周期；实际时长依弹幕运动参数变化。

## 实页实验

使用独立 `/blanc/22747736?liteVersion=true` 页，不改用户已安装组件、设置或来源，不发弹幕，不调用点赞/赠礼接口。

| 实验 | 实测结果 |
| --- | --- |
| 调用原生进入，约 1.2 秒后离开 | 对象仍在，结束时间延长约 1.202 秒，离开后继续向左移动 |
| 调用原生进入并跨过原定期限 | 开始时剩余约 2.75 秒；暂停期间坐标不变，但跨期后对象已被回收；DOM 仍连接在页面，样式已重置 |
| 仅在该对象上保护悬停期间的 `shouldDestroy`，配合原生进入/离开 | 开始时剩余约 2.109 秒；暂停约 12.052 秒，坐标变化为 0；对象跨期仍保留；离开后结束时间延长约 12.052 秒，原对象继续向左移动 |

局部保护只让悬停对象暂不按时到期，其他时候委托原判断。离开时先调用原生时间补偿，再恢复原判断；测试结束删除临时的实例属性，原型方法始终不变。没有拦截全局 DOM 删除，没有把回收节点塞回页面，没有自建续播动画。

## 实例入口与维护成本

`window.EmbedPlayer.instance` 暴露的是播放器门面，不直接给出弹幕管理器；DOM 自有属性也没有原生渲染对象引用。

在隔离页中短暂使用函数断点捕获引擎实例，读取路径为引擎的 `danmaku.core.manager.visualArray`；可用对象的 `element` 与命中的原生 DOM 精确对应。随后验证了一次性包装 `LiveDanmakuEngine.default.prototype.handleSocketMessage`：收到下一条自然消息时捕获同一实例，立即恢复原方法并原样转发消息；四秒超时也恢复。实测成功，且拿到的实例与断点捕获一致。这是研究可行入口，尚不是承诺稳定的公共接口。

对用户已有页尝试过调试器堆对象查询，两次分别超时，未采用此方式作为实现入口；没有写入该页业务对象或配置。后续实验全部放在独立页。

## 判断与未覆盖项

已有证据表明：可以用原生动画配合一处实例级回收保护实现自然续播，比复制后重建运动更直接。但仍依赖引擎内部结构和方法名，不能因此宣称比稳定快照更可靠。

继续验证需要覆盖：密集弹幕下的轨道碰撞/遮挡、连续多次悬停、多个对象切换、滚动/反向/顶部/底部/特殊弹幕、播放器重建、全屏切换、关闭组件和换房时的恢复。尤其暂停对象的时间参数延后更新是否影响其他弹幕的避让，本轮未证实。

现阶段保留快照方案；不加入常驻原型补丁。若以后推进原生适配，应限制引擎版本和结构，限时捕获后恢复入口，在不能确认状态时使用已有快照方案，所有对象保护都必须可撤销。

## 开发版接入（2026-11-05）

`native.ts` 已实现限时一次性实例捕获及实例级回收保护，接入现有组件；只有支持的滚动/反向模式使用原生路径，其余继续使用快照。入口包装在捕获、超时或关闭时还原；每次只保护当前对象，离开时补偿时间并恢复原回收判断。没有采用常驻原型钩子。

最新构建通过 DevClient 安装、刷新真实 `/blanc/22747736?liteVersion=true` 后实测：

- 真实鼠标移动触发原生暂停，无快照；停留 12.5 秒后正文、位置、暂停状态和操作栏均保持，右侧列表持续更新；移开后原节点恢复运动，操作栏关闭。

- 关闭原生选项后使用快照，保持播放器裁切；停用组件后快照、选中标记及工具栏均清理。
- 原生暂停期间停用组件，原生暂停样式解除，选中标记清理；重新启用可继续使用。

真实顶部/底部特殊模式、原生全屏以及密集弹幕轨道碰撞仍需用户体验验收；没有据此声称所有模式都已验证。正式发布来源未修改，开发版两组件维持 localhost 调试。
